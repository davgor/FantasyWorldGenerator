# ML-03 — Native kernel and UnrealWorldGen push

## Requested behavior

Ship a runtime `.uplugin` whose in-process API can generate a recipe-3 world (not only the bounded counter), materialize it in sibling **UnrealWorldGen**, and prove that same loop in a packaged Win64 build.

## Push to Unreal — in this epic

These three gaps **are ML-03**. They are not a later adapter project and not deferred to asset production:

1. **`.uplugin` + in-process generate API.** `Unreal/FantasyWorldGenerator/` wraps `Core/`. Native core implements world genesis (seed → visualization envelope + on-demand samples). The counter kernel remains, but counter-only is not this finish line. Owned by [ML-03d](../backlog/ML-03d.md) (native generate) and [ML-03e](../backlog/ML-03e.md) (plugin wrapper).
2. **UnrealWorldGen importer.** Z-up mapping (east→X, north→Y, up→Z), metres → centimetres once, Landscape from detailed samples, asset-ID → Unreal object-path registry, hub generate on interact. Owned by ML-03e; mapping/registry schema fixtures owned by ML-03d.
3. **Packaged generate → materialize loop.** Clean Win64 cooked run of the entire path, exact package digest recorded. PIE-only does not close the epic. Owned by ML-03e. Hosted CI cook may follow the digest.

Python JSON export already exists; it does not satisfy any of the three. No sidecar, spawned Python, or Editor Python.

## Proposed mechanism

Keep `Core/` free of Unreal types; wrap it in `Unreal/FantasyWorldGenerator/`; UnrealWorldGen (Unreal 5.8, local Win64) is the consumer for compile, load, on-demand native genesis, importer materialize, and packaged Win64 execution.

## Dependencies and unresolved decisions

Depends on ML-02. Recorded: plugin/module `FantasyWorldGenerator`; engine 5.8.2 / project 5.8; first platform Win64; private distribution (decision 017). Genesis is in-process native (decision 018). Python sidecar/subprocess/Editor Python are out. Unreal frame is east→X, north→Y, up→Z centimetres.

Still required to close this parent: the three push-to-Unreal items above via ML-03d and ML-03e; hosted CI/immutable channel if not produced during 03e.
