# ML-03 — Native kernel and UnrealWorldGen push

## Requested behavior

Ship a runtime `.uplugin` whose in-process API can generate a recipe-3 world (not only the bounded counter), materialize it in sibling **UnrealWorldGen**, and prove that same loop in a packaged Win64 build.

## Push to Unreal — in this epic

These three gaps **are ML-03**. They are not a later adapter project and not deferred to asset production:

1. **`.uplugin` + in-process generate API.** `Unreal/FantasyWorldGenerator/` wraps `Core/`. Native core implements world genesis (seed → visualization envelope + on-demand samples). The counter kernel remains, but counter-only is not this finish line. Owned by [ML-03d](../backlog/ML-03d.md) (native generate) and [ML-03e](../backlog/ML-03e.md) (plugin wrapper).
2. **UnrealWorldGen importer.** Z-up mapping (east→X, north→Y, up→Z), metres → centimetres once, Landscape from detailed samples, asset-ID → Unreal object-path registry, hub generate on interact. Owned by ML-03e; mapping/registry schema fixtures owned by ML-03d.
3. **Packaged generate → materialize loop.** Clean Win64 cooked run of the entire path, exact package digest recorded. PIE-only does not close the epic. Owned by ML-03e. Hosted CI cook may follow the digest.

Python JSON export already exists; it does not satisfy any of the three. No sidecar, spawned Python, or Editor Python.

## Proposed mechanism

Keep `Core/` free of Unreal types; wrap it in `Unreal/FantasyWorldGenerator/`; UnrealWorldGen (Unreal 5.8, local Win64) is the consumer for compile, load, on-demand native genesis, importer materialize, and packaged Win64 execution.

## Dependencies and unresolved decisions

Depends on ML-02. Recorded: plugin/module `FantasyWorldGenerator`; engine 5.8.2 / project 5.8; first platform Win64; private distribution (decision 022). Genesis is in-process native (decision 018). Python sidecar/subprocess/Editor Python are out. Unreal frame is east→X, north→Y, up→Z centimetres.

Still required to close this parent: the three push-to-Unreal items above via ML-03d and ML-03e; hosted CI/immutable channel if not produced during 03e.

## Acceptance and evidence

PK02, PK03, PK04 (UnrealWorldGen packaged generate → materialize), PK06 (IDs/units/contact), PK08, PK10. A Python wheel, JSON export, descriptor-only plugin, PIE-only capture, HTTP lab, spawned Python, ID-less cubes, or mutable Actions artifact cannot satisfy this ticket.

### Acceptance

- **A1** Native in-process generate API — **accepted**. `Core/` generates the recipe-3
  world from a seed: plate layout, noise, erosion, the second tectonic epoch and relic
  incision, connected water, wind and rain, biome and landform labels, cold habitats,
  salinity and flood risk, plus on-demand detailed surface sampling, the coordinate
  frame and the registry loader. `tests/test_native_world.py` compares every produced
  layer against the Python reference world: identity layers exact, continuous fields
  inside `Fixtures/native-world-v1.json` (worst observed 4.5e-13 relative, from the
  platform `pow`). Native generate of a size-65 world: ~0.2 s against ~65 s in Python.
  **Included since 2026-09-18:** settlement fields, founded cities, city layout plans,
  regional roads and their `world_scene` polylines, all bit-compared against the oracle.
  **Not included:** plot geometry (footprints, walls, streets), nest anchors and the two
  age transitions — ML-03d steps (f) and (g) remain open, and ML-03d records what they
  depend on.
- **A2** `.uplugin` FantasyWorldGenerator — **accepted (headless + UBT game target)**.
  The archive vendors Core, the module compiles it, the frame mirror is deleted, and
  `Data/unreal-asset-registry-v1.json` is staged as a runtime dependency. PK10 is met
  for the game target; the editor target is blocked below.
- **A3** Unreal MCP — **not needed for this path**. Everything is driven headlessly by
  UnrealBuildTool and UAT; no editor session is required to compile or cook.
- **A4** Importer + hub — **implemented, not yet run**. UnrealWorldGen builds its hub
  in code (capsule pawn, one interactable, loading line, HUD report, code-spawned
  lighting on `/Engine/Maps/Entry`) and materializes the sampled surface as a runtime
  procedural mesh, one section per natural biome, materials resolved through the
  registry ([decision 019](../../docs/decisions/019-runtime-surface-not-landscape.md)).
- **A5** Packaged Win64 loop — **accepted**. A cooked Win64 executable generates and
  materializes with no editor and no Python: digest
  `ab8810a431c454573468e80cc6225796533ef2b1882d715c33908b4c019107cd`, 33,153 vertices in
  registry-painted biome sections, the native core's 16 cities, 13 regional roads and
  205 registry-resolved planned building slots drawn on that surface, collision within 0.018 cm of the drawn surface, frame checks
  passing from inside the shipped plugin, and identical replay for a repeated seed. Numbers and caveats in [ML-03e](../backlog/ML-03e.md). The cook ran
  against a copy of the consumer project because UnrealBuildTool refuses to build while
  the editor holds a Live Coding session; the canonical tree needs one cook with the
  editor closed to carry the same digest.
