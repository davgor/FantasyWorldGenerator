# ML-02 — Minimal bounded state/time/event kernel

## Requested behavior

Prove one pure, headless, persistent transition with bounded work, explicit simulation time, stable revisions, and idempotent accepted-event receipts.

## Proposed mechanism

Implement immutable candidate evaluation followed by explicit commit data. Start with one small generic transition, not damage, ecology, jobs, and factions simultaneously. Define duplicate, conflicting-payload, stale-revision, reordered-input, retry, checkpoint, serialization, and replay behavior.

## Dependencies and unresolved decisions

Depends on ML-01. Choose the first transition and maximum work budget. Durable storage and network transport remain game-owned.

## Acceptance and evidence

Pure fixtures prove exactly one effect for retries, rejection of ID reuse with different payload, deterministic ordering, no time advance over pending work, checkpoint/resume, finite serialization, and the declared numeric contract.


## Completion evidence — 2026-09-16

The first transition is an accepted-event counter with integer milliseconds, at most 64 input events/effects per command and 256 retained receipts. Full-interval overflow/capacity checks precede partial work. Immutable candidates capture base, normalized command, next state and effects; commit re-evaluates and fences the full current snapshot. Duplicate delivery/commit is idempotent, conflicting IDs fail, pending intervals cannot change or accept inserted work, and completed time does not advance until pending work finishes.

Twelve behavioral tests were added before implementation. Independent fixture states cover +5/+3/+2 with budgeted checkpoint and resume. Tests include input reorder, stale epochs/revisions, altered candidates, failed/repeated commit, bounded retention and resume in a fresh process. The installed wheel also resumed the checkpoint from outside the checkout. Full validation: 213 reference +55 facade/native-driver tests, provenance verification, lab smoke and reproducible asset exports/showcase.

No generator/asset/seed behavior changed; exhaustive asset bytes retain SHA-256 `128c7b20bb9c3fc427cabfb5070d7e4113b48585826a8ff8ddad8a0f935d8007`. `Contracts/kernel-v1.md` and the capability descriptor document the additive Python proof. Hosts still own atomic storage and external effect delivery; this is not a production world simulation. Next: ML-03 native wire contract and Unreal qualification.
