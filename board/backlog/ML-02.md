# ML-02 — Minimal bounded state/time/event kernel

## Requested behavior

Prove one pure, headless, persistent transition with bounded work, explicit simulation time, stable revisions, and idempotent accepted-event receipts.

## Proposed mechanism

Implement immutable candidate evaluation followed by explicit commit data. Start with one small generic transition, not damage, ecology, jobs, and factions simultaneously. Define duplicate, conflicting-payload, stale-revision, reordered-input, retry, checkpoint, serialization, and replay behavior.

## Dependencies and unresolved decisions

Depends on ML-01. Choose the first transition and maximum work budget. Durable storage and network transport remain game-owned.

## Acceptance and evidence

Pure fixtures prove exactly one effect for retries, rejection of ID reuse with different payload, deterministic ordering, no time advance over pending work, checkpoint/resume, finite serialization, and the declared numeric contract.
