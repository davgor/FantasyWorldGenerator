# World parameters

Every generated world carries the table it was generated from. `recipe.parameters` is the
whole control registry as the request resolved it, and `recipe.provenance` says, for each
control, whether the value came from the request's `overrides`, from a `world_size`
preset, from a bias, or from the default. A consumer holding a world document does not
have to consult this repository to learn what it could have asked for.

## What a bound is, and where it is stated

A control that takes a number publishes `min` and `max` alongside its default. Those are
not advice: a request carrying a value outside them is refused with the failure envelope,
which names the control, the value received, the bound violated and a value that would
work.

The grid range is the instance with the most history. It is declared in the registry's
bounds table (`Sim/icarus_sim/terrain_world.py:273`, `bounds`) and enforced by a separate
statement of the same integer in the request path
(`Sim/icarus_sim/terrain_world.py:488`, `over_capacity`), four hundred lines below it.

| bound | value |
|---|---|
| Grid size ceiling | <!-- conformance:version grid-size-max=1025 --> |

That marker is resolved from the bounds table, and the guard's own argument is resolved
independently and compared against it. The two are one fact written twice, and they
agreed until now because somebody checked - the same footing the Python and native grid
ceilings were on when they drifted. They can no longer move apart silently: a change to
either alone is reported as a mismatch naming both sites.

## What this does not establish

The bound is stated twice and cross-checked, not stated once. Deriving the guard from the
bounds table - so there is one statement rather than two agreeing ones - is a one-line
change to a provenance-pinned file and remains the better fix; see
[PRODUCT-PARAMETER-PROVENANCE](../../board/done/PRODUCT-PARAMETER-PROVENANCE.md) for why
it was not taken here and what it costs.

The published table says nothing about *which producer path* resolved a value beyond the
four-way `recipe.provenance` vocabulary. Two world documents generated by different entry
points at the same version are indistinguishable on that point.

This record claims no module. `Sim/icarus_sim/terrain_world.py` is on the uncovered
allowlist against [CONFORMANCE-DOCS](../../board/in-progress/CONFORMANCE-DOCS.md), which
owns placing it, and claiming it from here would take that decision out of their hands for
a record that describes one table inside it.
