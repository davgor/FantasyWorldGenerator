# LAB-018 — scoped adversarial review

Self-review compared the repaired settlement code with the deterministic generation, strict validation, and terrain-safe placement contracts in `docs/terrain-world-layers.md` and `docs/terrain-math-lab.md`.

## Findings and resolutions

The building-option parser normalized `count.profiles` to a set, then incorrectly applied raw-JSON list validation to that normalized value. Valid catalogue rows therefore stopped every generated world during settlement construction. The parser now distinguishes top-level raw profile lists from already-normalized count profiles while retaining strict rejection of malformed top-level values.

The building anchor collector accepted a cursor derived from the full eligible-node list, then used it directly against smaller river-frontier lists. A valid deterministic world could therefore raise `IndexError`. The collector now normalizes every incoming cursor to the candidate list before indexing.

The extended city-layout helper had also made the full graph a mandatory positional argument, breaking the pre-extension terrain-constraint unit test. The graph is optional for compatibility; production generation still passes it and building plans use it when present.

## Evidence and limitations

The focused city-layout tests pass, including deterministic full-world generation and the no-valid-anchor constraint case. The complete repository unit runner passes 112 simulation tests and 73 tooling tests. No canonical behavior changed: these repairs make the existing authored schema and documented deterministic planner executable, so no requirement or implementation-status prose change is warranted.

This is a source-only FantasyWorldGenerator review. It does not establish Unreal city instantiation, navigation, collision, packaging, performance, or visual quality. The review was performed by the implementing session rather than an independent reviewer.
